# MBOYO Production Scope

This document expands Tier 3 ("Production") from [MVP_SCOPE.md](MVP_SCOPE.md) into concrete non-functional and operational requirements. It answers "what does it take to run this for real" as distinct from "what features exist."

Per [WORKING_CONTRACT.md](WORKING_CONTRACT.md) non-goals, this is a **production-minded** architecture within capstone scope, not a fully hardened multi-region production deployment. The gap between the two is stated explicitly below rather than left implicit.

## Security

- All role-gated actions enforced at the API route and RLS layer; UI restrictions are convenience only ([AGENTS.md](../../AGENTS.md)).
- Service-role key, ML internal token, VAPID private key, session signing secret, and cron secret never reach client bundles — verified by a build-time check, not just code review convention.
- Raw evidence (photos, GPS-tagged media) served only through authenticated, role-checked, time-limited Supabase Storage URLs — never public buckets.
- Auditor role is strictly read-only, enforced by RLS, not just hidden UI actions.
- Dependency and secret scanning in CI before merge (deferred to a later infra block — tracked here as a Production Scope requirement, not yet implemented).

**Capstone-scope gap:** formal penetration testing, SOC2/ISO evidence collection, and third-party security audit are out of scope for this capstone and are Tier 4 (Future) at earliest.

## Reliability and Offline Guarantees

- Report creation has zero live-network dependency, verified by an automated test that runs the creation flow with network mocked/disabled.
- Sync is idempotent: replaying the same local report multiple times against the server produces exactly one incident record, verified by a dedupe-key test.
- Background Sync retries transparently; sync failures surface a visible, non-blocking status to the Reporter rather than failing silently.
- `apps/ml-api` failure (timeout, 5xx) does not block report ingestion — analysis jobs queue and retry independently of the report-submission path.

**Capstone-scope gap:** multi-region failover and disaster-recovery drills for MBOYO's own infrastructure (as opposed to the disasters it reports on) are Tier 4.

## Observability

- Structured logging across `apps/web`, `apps/ml-api`, and `apps/worker` with correlation IDs that let an Auditor or System Administrator trace a report through analysis, verification, and dispatch.
- Optional Sentry integration (`SENTRY_DSN`) for error tracking — not required for MVP, expected by Production tier.
- `analysis_jobs` table exposes status (`queued`, `processing`, `done`, `failed`) queryable by System Administrator for service-health visibility.

## Data Governance

- Retention policy for raw evidence is configurable by System Administrator and enforced by a scheduled job (not just documented intent).
- Sensitive imagery (e.g., identifiable individuals, deceased persons) handling is governed by the sensitive-imagery risk entry in [RISK_REGISTER.md](RISK_REGISTER.md) — access is role-gated and never included in public exports.
- Exports (CSV/GeoJSON) generated by Response Coordinator exclude any field not relevant to operational response (e.g., no reporter PII beyond what's operationally necessary).

## ML Operations

- Every model promoted to production-serving passes the release gate defined in [SUCCESS_METRICS.md](SUCCESS_METRICS.md), evaluated on a held-out, untouched test set, with the evaluation report checked into `ml/reports/` and dated.
- If a release gate fails, the system falls back to advisory-only mode (see [SUCCESS_METRICS.md](SUCCESS_METRICS.md) release gate section) rather than serving an unvalidated model as authoritative.
- Model version is recorded on every `analysis_jobs` row so Auditor can trace which model version produced which probability.

## Accessibility and Web Performance

- WCAG 2.1 AA target across Reporter, Verifier, Coordinator, Administrator, and Auditor UIs.
- Web performance budgets tracked per [SUCCESS_METRICS.md](SUCCESS_METRICS.md) (Core Web Vitals on representative mid-range mobile hardware, given Reporter's likely device profile in the field).

## External Dependencies

- Supabase (auth, Postgres/PostGIS, Storage, Realtime) is a hard dependency; an outage degrades the platform to read-only/local-queue-only mode for Reporters (offline-first design absorbs this) but blocks Verifier/Coordinator/Auditor workflows. Documented in [RISK_REGISTER.md](RISK_REGISTER.md).
- Map tile provider (MapTiler/MapLibre style) outage degrades Coordinator's map view; incident list/table view must remain usable without the map.
- Gemini, when enabled, is advisory-only; its unavailability must never block the Verifier decision path.
